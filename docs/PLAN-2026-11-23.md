# 方案书（2026-11-23）—— 从"换色插件"到"可模块化的默认主题"

> 背景：v1.2 只做了 L1 里的 18 个 token，效果"差强人意"。本方案把能力分层、定先后、定复用来源，
> 每一层都用**已有前辈实现**做依据，不自己造轮子。
> 目标端：**桌面端为主**，`web` profile 只作开发沙盒。

---

## 0. 一页结论

| 问题 | 答案 |
|---|---|
| DSH 能美化的部分 | 颜色（133 token）、语义区块（37 个 slot + `data-*` 锚点）、密度/字体（88 个 `--dsh-*`）、
图标（196 个 symbol）、覆盖层（点击特效/页内宠物/开屏/壁纸）、系统级（真桌宠窗口/WE 场景） |
| 不能改的 | 三栏布局、前端路由/新页面、组件交互逻辑、窗口外框、`root` slot |
| 我们的定位 | **默认主题做到"成品级"** + 把能力边界写成矩阵；开屏/点击特效/壁纸以**模块**形式挂载 |
| 不复用生态头部产品的原因 | 宠物 6632★、壁纸引擎 7919★、开屏 427★ 均已占位；正面重建不划算，借方法即可 |

## 1. 能力分层与做法

| 层 | 做什么 | 具体手段 | 复用来源 | 验收 |
|---|---|---|---|---|
| **L1 颜色** | 133 个 token 全量覆盖（明暗双套） | `overrideTokens` + 逐项验证消费点 | `theme-pack`（129/129 覆盖）、`catppuccin`（逐条覆盖） | 每个 token 找到消费元素或以"未消费"记录 |
| **L2 区块** | 侧栏 / 输入区 / 消息卡 / 代码块 / 按钮 / 弹层 | 只用 `data-slot` 与稳定 `data-*` 锚点，不用哈希类 | `dsh-skins`（L1 tokens + L2 语义属性契约）、`any-background`（稳定标记纪律） | 每个选择器写明锚点与验证版本 |
| **L3 密度** | 字号、行高、圆角、阴影、间距 | 88 个 `--dsh-*` + 自有 `--bj-*` | `endfield`（直角/圆角模式）、`bloom`（材质） | 980×640 不遮挡；缩放不破版 |
| **L3+ 图标** | 挑 12–20 个高频图标换成主题风格 | `theme` 服务 icon 接口（限 `ICON_SYMBOLS`，SVG 需 viewBox、无 style/script） | 无成熟先例，接口已实测存在 | 逐个替换后无破图、无布局位移 |
| **L4 覆盖层** | 点击特效 → 开屏 → 壁纸层 → 页内宠物 | `shell.overlay` + client；开屏另需首帧 | `bafx`（点击特效，MIT，跨端一致）、`boot-suite`/`550c-boot`（开屏）、`wallpaper-engine`（WebWallGL，MIT）、`whale-girl`（页内宠物） | 可开关、卸载无残留、减动效生效 |
| **L4+ 首帧** | 开屏抢在 React 之前 | `webserver/index-inject` | `550c-boot`（声称桌面有效，待验） | **桌面端实测**是否露 Loading 卡片 |
| **L5 系统级**（可选） | 真桌宠窗口、WE 场景渲染、音频子进程、标题栏透明 | host 侧 Electron/子进程 | `dsh-pet`（MIT）、`wallpaper-engine`（MIT）、`startup-screen`（MIT） | 单独验收，不进主流程 |

**桌面端可行性**

| 能力 | 桌面端 | 依据 |
|---|---|---|
| L1 / L2 / L3 / 点击特效 / 页内宠物 / 壁纸层 | ✅ 同一套 client | `bafx`：「Web 与桌面端同一套实现，不依赖 tapIndex」 |
| 开屏（client 覆盖层） | ✅ | 同上 |
| 开屏（首帧注入） | ⚠️ 待实测 | 550c-boot 声称有效；`tapIndex` 在桌面确认是死代码 |
| 真桌宠窗口 / 音频子进程 | ✅ 但属系统级 | `dsh-pet` 明确"无显示环境跳过桌面窗口" |

## 4. 明确不做

1. **不重排布局**：三栏结构、面板位置、侧栏顺序 —— 无接缝，硬改必碎。
2. **不新增前端页面/路由**：只加 HTTP 路由。
3. **不搬 FGO 美术**：默认主题只用色值、排版、自绘 SVG、开源字体。
4. **不重建生态头部产品**：宠物/壁纸引擎/开屏只做"模块化接入"，不重写。
5. **不碰 `desktop` 数据**：只加一条插件依赖；验证前先备份 profile 记录（记住当前状态）。

## 5. 风险与对策

| 风险 | 对策 |
|---|---|
| L2 选择器随构建变化 | 只用 `data-slot` / `data-*`；选择器集中在 `overrides.tier3.css`，文件头写验证版本 |
| token "写了不生效" | 每个 token 必须找到消费元素；找不到就标"未消费"，不写进主题 |
| 桌面首帧未知 | v1.3 先实测，再决定 v1.5 开屏走哪条路 |
| DSH 版本迭代快（约 1.77 天/版） | 窄接缝 + 每版跑兼容检查 + 超范围由宿主跳过 |
| 与头部项目撞车 | 主题做"完成度 + 矩阵结论"，功能做"模块"，不做同质竞争 |

## 6. 需要你决定的两件事

1. **授权一次桌面端安装**（会重启 DSH Desktop，只加一条插件依赖，不碰会话数据）—— 没有它，v1.3 的"桌面为主"就无法验收。
2. **视觉方向**：默认「纸白 + 金」还是「深色 + 金」（当前浅色为默认、深色为预览）。选定后 v1.3 一次做透，不再反复。
