# ROADMAP.md —— 阶段计划、版本映射与回滚

> 详细方案（能力分层、复用来源、成本与取舍）见 [`PLAN-2026-11-23.md`](./PLAN-2026-11-23.md)。

## 0. 工作规则（写在最前，避免再跑偏）

1. **先调研，再动手**：任何新能力先找官方契约 + 开源参考，结论写进 `research/RESOURCES-*.md`，再写代码。
2. **不闭门造车**：能用既有方法/资源就不重造；借用必须看许可，写清"借了什么、没借什么"。
3. **术语一律用 DSH 官方说法**：主题 token、slot、bundle、client module、webServer 路由、配置文件。
   项目名只是命名趣味，不作为产品概念。
4. **每版必须自验证并留痕**：`scripts/release_check.py` + 本版专属验收 → 写 `JOURNAL.md` → 打阶段标记。
5. **阶段标记是回滚点**：`stage-NN-vX.Y` 轻量标签，推送到远端；回滚方式见 §4。

## 2. 每个阶段的固定动作

```
调研（写 RESOURCES / 查契约）
  → 写代码（最小可用，不铺开）
  → scripts/release_check.py
  → 本阶段验收（实测命令 + 浏览器验证）
  → 更新 VERSION / CHANGELOG / TODO / MODULARITY / JOURNAL
  → 提交 + 推送 + 打 stage 标签
```

## 4. 阶段标记与回滚

| 项 | 约定 |
|---|---|
| 标签名 | `stage-NN-vX.Y`（如 `stage-03-v1.2`） |
| 类型 | 轻量标签（指向提交，不打额外对象） |
| 推送 | 与提交一起推到远端，`refs/tags/*` 可见 |
| 回滚 | `git reset --hard stage-03-v1.2`（本地）／远端同步由下一次推送覆盖 |
| 记录 | 每个标签在 `JOURNAL.md` 有对应条目，写清"这一版能做什么、不能做什么" |

## 5. 风险与对策

| 风险 | 对策 |
|---|---|
| DSH 版本快（约 1.77 天/版） | 只用 4 条窄接缝；每阶段跑一次兼容检查；超范围由宿主跳过 |
| C 层选择器随构建变化 | 选择器集中在 `overrides.tier3.css`，文件头写验证版本 |
| 主题写坏导致界面不可用 | v1.8 安全模式：配置异常回退默认 + 一键停用 |
| 网络不通（本机 hosts 劫持） | 推送走 Git Data API；拉取走 DoH + 直连 IP |
