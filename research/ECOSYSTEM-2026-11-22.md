## 4. 机制实测（这才是能抄作业的部分）

### 4.1 主题 token：**14 个只是"广告牌"，实际可覆盖 129 个**【实测】

`rpglit/dsh-client-ui-theme-pack` 的 `lib/types/tokens.js`（380 KB，含生成器注释）：

```
Theme catalog generated by tools/gen_tokens_ts.py from artifacts/ui-themes/tokens.json
(v2: 10 core + 129 full tokens per theme)
```

- 该文件里唯一 `--dsw-*` 名 **129 个**：**117 个 `alias` + 11 个 `specific`**（另有 1 个重复计数）
- 插件调用 `overrideTokens`（3 处）+ `slots.register`（2 处）→ 走的是**官方 API**，不是 CSS 硬注入
- 结合本机 `validateOverrides` 源码：**它不校验 token 名是否在 14 项白名单内**

**推论**：`Theme.listTokens` 的 14 项只是"被推荐/被列举"的集合；`overrideTokens` 接受任意 CSS 变量名，
只要该变量**真的被界面消费**，覆盖就生效。竞品的 129 项是**实测筛出来的有效集合**。

> ⚠️ 这条**尚未在我们自己的实例里验证**（需要写一个覆盖 `--dsw-specific-sidebar-fill` 之类非白名单项的探针）。
> 未验证前，`docs/TODO.md` 的 `D17` 只能算"半修正"。

### 4.2 开屏：host 注入 + 自定义路由 + 本地 JSON，和我们的设计完全同路【实测】

`6shenhonghong9/dsh-startup-screen` 的 `lib/index.js`（Host 半侧）注释原文：

```
做三件事：
  1) 在 index.html 里注入「启动界面」：首屏兜底黑幕 + 关键 CSS + 配置 + 运行时
  2) 提供 /dsh-startup/splash.css · splash.js · config 三个路由
  3) 把配置持久化到 ~/.dsh/dsh-startup.json（设置页经 /dsh-startup/config 读写）
```

- 签名命中：`webserver`×14、`webServer`×14、`requestRejection`×2 → **鉴权自检也做了**
- `lib/splash.js` 67 KB 零依赖运行时，**在 React 挂载前接管首屏**，含 `sessionStorage` 去重
- 安装方式：`dsh plugin --profile web add dsh-startup-screen`，或市场页一键装；本地开发 `add link:<目录>`
- 桌面端额外做「标题栏透明化」（Windows）

→ **结论**：项目文档里的 271ms 分析与双半边结论**是对的**，且已被头部竞品独立验证。
我们的 P2 不需要重新发明，但要做得比它更"成品化"（灵衣叙事 + 与素材系统联动）。

## 5. 空位分析：DSH-SDT 该站哪

| 观察 | 对 SDT 的含义 |
|---|---|
| 125/170 做配色，44 做壁纸，35 做玻璃 | **"我也能换颜色"没有意义**。必须换赛道叙事，不是加色板 |
| 只有 10 个碰开屏，头部 1 个（872★） | 开屏是**少数还值得做深**的接缝；但必须做出它没有的东西 |
| FGO 相关仅 1 个（Saber 壁纸皮肤，0★），无"灵衣/缝制/衣柜"框架 | **概念位是空的** → SDT 的定位本身就是差异点 |
| 29+15 个仓库许可不明，AGPL 6 个 | 许可干净（MIT 自己的代码）+ 不抄 → 可被市场与二次分发接受 |
| 出现"皮肤中心/市场/加载器"（3 个 + 多个 npm 包） | 用户已被教育出"换装"心智 → **"灵衣衣柜"正好接在这个心智上** |
| 大量项目靠 `!important` / 深选择器硬改 | 深改=易碎（DSH 1.77 天一个版本）→ **窄接缝 + 可降级**仍是我们的护城河 |

**建议的差异化主张（三条）**：

1. **叙事**：不是"主题/皮肤"，是 **灵衣缝制** —— 衣柜（已缝好的灵衣）+ 缝制台（Agent 适配素材）+ 图鉴（可切换的整套外观）。
   同赛道没人占这个概念，且它能自然承载"素材替换"这个我们已经设计好的能力。
2. **工艺**：**129 项 token 全覆盖 + 明暗成对 + 对比度自检**（竞品只有头部做到了 WCAG AA，多数没做）。
3. **耐久**：窄接缝（4 条）+ 单点失效降级 + 每版自验证报告。生态里"上版就碎"的项目非常多，这是可展示的差异。
